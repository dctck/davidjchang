Reframing a complex wallet around user intent so common actions start before users have to think about networks, addresses, or system structure.

The Problem

Users had to navigate wallets, networks, and addresses before they could do something as simple as Send.

What Users Were Struggling With

"It takes too many steps just to send ENJ."

"Switching between multiple wallets and addresses is confusing."

"Why do I have to dig into each coin just to send or receive?"

The Product Reflected the System, Not the User's Goal

The old navigation mirrored how the wallet was technically structured:

Wallets (collapsible groups)
Addresses (grouped by networks like ETH, BTC)
Asset details
Only then: Send or Receive

The hierarchy was technically accurate, but it made simple tasks feel complicated. The redesign flipped that order: start with the action, then reveal the required wallet and network details only when they matter.

Research & Discovery

Prioritize the Behavior Users Repeated Most

Transaction data showed that Send and Receive represented 49.3% of wallet activity, making them the clearest place to reduce friction first.

Competitive Analysis

I compared leading wallets to understand how they surfaced frequent actions. Many used strong brand colors to emphasize controls, but that competed with the wallet's most important information: balances and assets.

Phantom Wallet

Prominent wallet switching

Trust Wallet

Low-emphasis action controls

Coinbase Wallet

Multiple actions surfaced up front

Visual Priority: Keep Financial Data Dominant

Rather than using strong brand colors for every action, I kept the controls visually quieter with icon-and-label pairings so balances and assets remained the primary focus.

Different Users Shared the Same Friction

Power users, newer users, and game developers had different levels of complexity, but all three groups were slowed down by the same thing: too much navigation before a simple action.

Power Users

Multiple wallets for different purposes, trades frequently

New Users

Single wallet, basic crypto transactions only

Game Developers

Needs both mainnet and testnet wallets for development

Solution Design

Make the Action the Entry Point

The Quick Actions bar let users start with what they wanted to do instead of where the asset lived. Send and Receive solved the highest-frequency need, while Stake and Mint used the same high-visibility area for product discovery.

UX SOLUTION

Let the Asset Narrow the Technical Choices

Challenge

After choosing Send, the next question was what information should come first.

Asset first, network details second

  1. 1. Choose the asset they want to send
  2. 2. Choose from compatible source addresses
  3. 3. Choose the destination and amount

Selecting the asset first let the product narrow compatible addresses automatically, turning a technical search across networks into a guided flow.

Keep Advanced Wallet Structure Available Without Leading With It

New Wallet Selector

A global wallet selector kept multi-wallet management one tap away for power users while staying out of the main flow for everyone else.

Surface Network Context Before It Becomes a Mistake

Outcomes

Higher Activity After Launch

Transactions per active user increased after launch alongside the shorter transaction flow.

Fewer Steps for Common Transactions

Common transaction flows were reduced by 60%, replacing several layers of navigation with an action-first path.

One Surface Served Both User and Business Goals

The same high-frequency area that simplified Send and Receive also gave strategic features like Stake and Mint a natural place to be discovered.

What I Learned

Intent Can Be a Better Navigation Model Than Hierarchy

For high-frequency tasks, a navigation model based on user intent can be more useful than exposing the product's internal structure first.

Better UX Can Also Improve Feature Discovery

Strategic features gained visibility by being placed around a behavior users were already repeating, rather than through added promotional UI.
